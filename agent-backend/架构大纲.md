# Agent 后端架构大纲

## 一、整体架构分层

```
┌──────────────────────────────────────────────────────────────┐
│                       客户端 (Vue/React/小程序)               │
└──────────────────────────┬───────────────────────────────────┘
                           │ HTTPS
┌──────────────────────────▼───────────────────────────────────┐
│  ┌─ Nginx 反向代理 ──────────────────────────────────────┐  │
│  │  SSL 终止 / 静态资源 / 限流 / WebSocket 代理            │  │
│  └────────────────────────────────────────────────────────┘  │
├──────────────────────────────────────────────────────────────┤
│  ┌─ API 路由层 (src/api/routers/) ───────────────────────┐  │
│  │  参数校验 / 权限检查 / 请求分发                          │  │
│  └────────────────────────────────────────────────────────┘  │
│  ┌─ 中间件层 (src/middleware/) ──────────────────────────┐  │
│  │  日志 / CORS / 限流 / 异常处理 / 注入防护 / 隐私脱敏    │  │
│  └────────────────────────────────────────────────────────┘  │
│  ┌─ 服务层 (src/services/) ─────────────────────────────┐  │
│  │  会话管理 / 限流逻辑 / 缓存 / 反馈 / 异步任务            │  │
│  └────────────────────────────────────────────────────────┘  │
│  ┌─ 核心引擎 (src/core/) ───────────────────────────────┐  │
│  │  Agent工厂 / LangGraph Agent / RAG 检索 / 工具集       │  │
│  └────────────────────────────────────────────────────────┘  │
│  ┌─ 数据层 (src/models/ + src/db/ + src/cache/) ────────┐  │
│  │  PostgreSQL ORM / 异步会话 / Redis / 向量存储          │  │
│  └────────────────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────────────────┘
                           │
      ┌────────────────────┼────────────────────┐
      ▼                    ▼                    ▼
  PostgreSQL           Redis              DashScope/
  (会话/消息/           (缓存/限流/          DeepSeek
   反馈/向量库)           任务队列)           (LLM API)
```

### 2. src/ 源码详细说明

#### 2.1 应用入口 + 配置

| 文件 | 核心功能 | 详细说明 |
|------|---------|---------|
| `main.py` | **应用入口** | 1. 创建 FastAPI 实例<br>2. 按顺序初始化：日志 → LangSmith → CORS → 异常处理 → 中间件 → 生命周期(DB/Redis连接) → 路由注册<br>3. 开发环境用 `uvicorn --reload` 热重载 |
| `config.py` | **集中配置** | 1. 继承 `pydantic-settings.BaseSettings`，自动读取 `.env`<br>2. 管理所有可配项：API密钥、数据库连接、Redis、日志级别、限流参数等<br>3. 启动时验证必需的配置项是否存在，缺失则报错退出 |
| `config_env.py` | **多环境说明** | 文档性质，说明 development/staging/production 三种环境的配置差异 |

#### 2.2 路由层（api/）

**职责：参数校验、权限检查、请求分发。不包含业务逻辑。**

| 文件 | 核心功能 | 请求流程 |
|------|---------|---------|
| `routers/health.py` | **健康检查** | `GET /api/v1/health` → 检测 PostgreSQL 连通性 → 检测 Redis 连通性 → 返回各组件状态 + 版本号 |
| `routers/chat.py` | **对话接口（核心）** | `POST /api/v1/chat/completions` → ① 限流检查 → ② 加载会话历史 → ③ 检查缓存 → ④ 调用 Agent → ⑤ 返回流式/非流式回复 → ⑥ 异步保存消息 → ⑦ 更新会话标题 |
| `routers/auth.py` | **认证接口（可选）** | `POST /api/v1/auth/login` → 验证账号密码 → 签发 JWT Token<br>`POST /api/v1/auth/refresh` → 刷新 Token |
| `deps.py` | **依赖注入** | 提供 FastAPI `Depends()` 函数：<br>`get_db()` → 注入 SQLAlchemy 异步会话<br>`get_redis()` → 注入 Redis 连接<br>`get_current_user()` → 解析 JWT Token 获取用户身份 |

#### 2.3 中间件层（middleware/）

**职责：横切关注点，请求/响应生命周期中的通用处理。**

| 文件 | 核心功能 | 执行顺序 | 详细说明 |
|------|---------|---------|---------|
| `cors.py` | **跨域配置** | 第 0 层（最外层） | 设置 CORS 策略（允许的前端域名、HTTP 方法、暴露的响应头） |
| `exception_handler.py` | **全局异常处理** | 第 1 层 | 捕获所有未处理的异常 → 转换为统一 `{error_code, message}` JSON 格式 → 记录异常栈到日志 → 返回对应 HTTP 状态码 |
| `prompt_injection.py` | **Prompt注入防护** | 第 2 层 | 检测用户输入中的注入模式（"忽略指令"、DAN 越狱、系统命令执行、Base64 编码绕过等） → 高于阈值则阻断并返回 400 |
| `privacy_filter.py` | **数据隐私脱敏** | 第 3 层 | 检测文本中的手机号/身份证号/邮箱/银行卡号等 PII → 替换为脱敏格式 → 确保日志和数据库中不存储明文敏感信息 |
| `rate_limit.py` | **请求限流** | 第 4 层 | 滑动窗口算法 → 从 Redis 读取计数器 → 超过阈值返回 429 → 刷新 TTL |
| `logging_mw.py` | **请求日志** | 第 5 层（最内层） | 记录每次请求的方法/路径/状态码/耗时 → 关联 request_id 方便排查 |
| `logging_config.py` | **日志系统初始化** | 启动时执行 | 配置 logging：<br>通过 src/logger/logger.py 统一管理日志输出 |

#### 2.4 核心引擎层（core/）

**职责：项目独有的核心业务逻辑。** 这是最关键的层级。

**Agent模块（core/agent/）**

| 文件 | 核心功能 | 详细说明 |
|------|---------|---------|
| `kefu_agent.py` | **客服 Agent** | 1. 使用 `create_agent` / `ChatTongyi` 构建 LangGraph agent<br>2. 绑定工具（订单查询/退款处理）<br>3. 注册 middleware（前置记录开始时间、后置追加统计信息）<br>4. 设置 prompt（角色定义 + 工具调用规则 + JSON 输出格式） |
| `factory.py` | **Agent 工厂** | 1. 根据用户意图（order_query / refund / complaint / general）选择不同的 Agent 配置<br>2. 支持动态切换模型（简单问题用小模型、复杂问题用大模型）<br>3. 返回统一的 `Runnable` 接口给服务层调用 |

**RAG模块（core/rag/）**

| 文件 | 核心功能 | 详细说明 |
|------|---------|---------|
| `embedding.py` | **文本向量化** | 1. 加载本地 embedding 模型（sentence-transformers）<br>2. 提供 `embed_text(text) → list[float]`<br>3. 提供 `embed_batch(texts) → list[list[float]]` |
| `vector_store.py` | **向量存储操作** | 1. 连接 PGVector（PostgreSQL + pgvector 扩展）<br>2. `add_documents(docs) → None`：文档分块后写入向量库<br>3. `search(query_vector, top_k) → list[Document]`：余弦相似度搜索<br>4. 支持 metadata 过滤（按文档集合/时间范围筛选） |
| `retriever.py` | **检索器** | 1. 封装 embedding + vector_store 的调用链<br>2. `retrieve(query, filters, top_k) → list[Document]`<br>3. 结果格式化为 Agent context 需要的格式，并附带引用信息 |
| `document_loader.py` | **文档解析入库** | 1. 支持 PDF/Word/Markdown/纯文本格式<br>2. 解析后自动分块（按段落/固定 token 数）<br>3. 写入向量库 + 记录文档元数据到 PostgreSQL<br>4. 作为异步任务运行（避免阻塞 API） |
| `citation.py` | **引用溯源** | 1. 定义引用数据结构（doc_id / title / chunk_index / chunk_text / score）<br>2. 将检索结果的引用信息注入到 Agent 的 context 中<br>3. 从 LLM 回复中提取引用的文档编号<br>4. 将引用记录存储到消息的 metadata 字段 |

**工具模块（core/tools/）**

| 文件 | 核心功能 | 详细说明 |
|------|---------|---------|
| `order.py` | **订单工具** | 1. `dingdan_get(dingdan_id) → str`：查询订单详情（模拟数据或真实 API）<br>2. `tuihuo(dingdan_id, why) → str`：处理退款申请 |
| `customer.py` | **客户工具** | 1. `get_customer_info(customer_id) → str`：查询客户信息<br>2. `update_customer_info(customer_id, data) → str`：更新客户资料 |

**LangSmith追踪（core/）**

| 文件 | 核心功能 | 详细说明 |
|------|---------|---------|
| `langsmith.py` | **LLM 调用追踪** | 1. 设置环境变量启用追踪<br>2. 配置项目名称和采样率<br>3. 条件启用（只在配置了 API Key 时开启）<br>4. 可视化 Agent 决策链路、Token 消耗、响应延迟 |

#### 2.5 服务层（services/）

**职责：跨模块的业务编排。** 服务层不直接操作数据库，而是调用 models 和 core 的组合。

| 文件 | 核心功能 | 详细说明 |
|------|---------|---------|
| `conversation.py` | **会话管理** | 1. `create_conversation()` → 创建新会话<br>2. `load_history(session_id, limit)` → 加载历史消息 → 转换为 LangChain 消息格式<br>3. `save_message(session_id, msg)` → 保存新消息到数据库<br>4. `update_title(session_id, title)` → AI 自动生成会话标题 |
| `rate_limiter.py` | **限流服务** | 1. 滑动窗口算法实现<br>2. `check(key, max_requests, window_seconds) → (allowed, remaining, reset_at)`<br>3. 支持按用户限流 / 按 IP 限流 / 按接口限流<br>4. 并发安全（Redis INCR + EXPIRE 原子操作） |
| `cache.py` | **响应缓存** | 1. 根据用户消息+意图生成缓存 key<br>2. `get_cached_response(key) → str | None`<br>3. `set_cached_response(key, response, ttl)`<br>4. `invalidate_cache(pattern)` — 数据更新时清除相关缓存<br>5. 适用场景：政策查询（长缓存）、订单状态（短缓存） |
| `feedback.py` | **用户反馈** | 1. 接收用户的评分/反馈<br>2. 存储到 PostgreSQL<br>3. 统计功能（平均分/各分数分布/趋势）<br>4. 反馈数据与 RAG 引用关联（哪些文档被引用后用户评价高/低） |
| `task_queue.py` | **异步任务队列** | 1. 封装 arq（基于 Redis 的轻量级任务队列）<br>2. `enqueue_ingest_document(file_path) → task_id` — RAG 文档入库<br>3. `get_task_status(task_id) → dict` — 查询任务状态<br>4. Worker 函数在独立进程中运行，不阻塞 API |

#### 2.6 数据模型层（models/）

**职责：定义数据库表结构和 ORM 映射。** 采用 SQLAlchemy 2.0 异步模式。

| 文件 | 核心功能 | 字段说明 |
|------|---------|---------|
| `base.py` | **ORM 基类** | 1. 声明 DeclarativeBase<br>2. 定义公共字段（id, created_at, updated_at） |
| `conversation.py` | **会话表** | 字段：id(UUID, PK), session_id(str, UNIQUE), user_id(str), title(str), status(str: active/archived), created_at, updated_at<br>索引：session_id 唯一索引, user_id 索引, status 索引 |
| `message.py` | **消息表** | 字段：id(UUID, PK), conversation_id(UUID, FK), role(str: user/assistant/tool/system), content(Text), tool_name(str?), tool_call_id(str?), token_count(int?), metadata(JSONB), created_at<br>索引：conversation_id 索引, (conversation_id, created_at) 复合索引 |

#### 2.7 数据传输对象层（schemas/）

**职责：定义 API 的请求和响应格式（Pydantic 模型）。** 不存数据库，只用于序列化/校验。

| 文件 | 核心功能 | 详细说明 |
|------|---------|---------|
| `chat.py` | **对话请求/响应** | `ChatRequest`: messages(list), session_id(str?), stream(bool?)<br>`ChatResponse`: reply(str), citations(list?), session_id(str) |
| `auth.py` | **认证请求/响应** | `LoginRequest`: username(str), password(str)<br>`TokenResponse`: access_token(str), token_type(str), expires_in(int) |
| `common.py` | **通用模型** | `ErrorResponse`: error_code(str), message(str), detail(Any?)<br>`PaginationParams`: page(int), page_size(int)<br>`PaginatedResponse`: items(list), total(int), page(int), page_size(int) |

#### 2.8 基础设施层

| 文件 | 核心功能 | 详细说明 |
|------|---------|---------|
| `db/session.py` | **数据库连接** | 1. 创建 AsyncEngine<br>2. 创建 async_sessionmaker<br>3. 提供 `init_db()` / `close_db()` 供生命周期调用<br>4. SQLAlchemy 2.0 async 方式 |
| `cache/redis.py` | **Redis 连接** | 1. 创建 aioredis/redis.asyncio 连接池<br>2. 提供 `init_redis()` / `close_redis()`<br>3. 封装常用操作（get/set/incr/exists/expire） |

## 三、一次典型请求的完整链路

```
用户发送： "我的订单 dingdan_id_02 发货了吗？"

                           前端
                            │
                            ▼
┌── 1. Nginx ──────────────────────────────┐
│   HTTPS 解密 → 检查限流 → 转发到 uvicorn │
└──────────────────────────────────────────┘
                            │
                            ▼
┌── 2. CORS 中间件 ────────────────────────┐
│   检查 Origin → 允许跨域                 │
└──────────────────────────────────────────┘
                            │
                            ▼
┌── 3. 异常处理中间件 ────────────────────┐
│   包裹整个请求，如果有异常统一格式化返回     │
└──────────────────────────────────────────┘
                            │
                            ▼
┌── 4. Prompt注入检测 ────────────────────┐
│   检查"忽略指令"等攻击模式 → 正常则放行   │
└──────────────────────────────────────────┘
                            │
                            ▼
┌── 5. 数据隐私脱敏 ──────────────────────┐
│   如果输入含手机号/身份证 → 替换为脱敏格式│
└──────────────────────────────────────────┘
                            │
                            ▼
┌── 6. 限流检查 ──────────────────────────┐
│   Redis INCR → 未超限则继续              │
└──────────────────────────────────────────┘
                            │
                            ▼
┌── 7. API 路由 ──────────────────────────┐
│   POST /api/v1/chat/completions         │
│   参数校验 → 依赖注入(get_db, get_redis) │
└──────────────────────────────────────────┘
                            │
                            ▼
┌── 8. 对话服务 ──────────────────────────┐
│   a) 加载历史消息（最近 N 条）           │
│   b) 检查缓存（是否命中相同的问过的）     │
│   c) 未命中 → 调用 Agent                │
│   d) 保存消息到 PostgreSQL               │
│   e) 异步更新会话标题                    │
└──────────────────────────────────────────┘
                            │
                            ▼
┌── 9. Agent 引擎 ────────────────────────┐
│   a) 构造 messages（system + context +  │
│      历史 + 当前问题）                   │
│   b) LLM 第一轮：决定调工具             │
│   c) 执行 dingdan_get("dingdan_id_02")  │
│   d) LLM 第二轮：组织回复 + JSON 格式化  │
└──────────────────────────────────────────┘
                            │
                            ▼
┌── 10. RAG 检索（如果需要知识库）───────┐
│   a) embedding 当前问题                 │
│   b) PGVector 相似度搜索 → top 5 chunk │
│   c) 注入到 Agent context 中            │
│   d) 记录引用信息到 message.metadata    │
└──────────────────────────────────────────┘
                            │
                            ▼
┌── 11. 响应处理 ────────────────────────┐
│   a) 缓存回写入 Redis                    │
│   b) 返回 JSON 响应                     │
│   c) 请求日志记录                       │
└──────────────────────────────────────────┘
                            │
                            ▼
           前端展示：回复 + 引用来源
```

## 五、安全防护矩阵

```
攻击类型            防护模块                   防护位置
─────────          ────────────              ──────────
Prompt 注入         prompt_injection.py      中间件（请求进入时）
数据泄露            privacy_filter.py         中间件（日志/响应输出时）
CSRF/XSS           CORS + HTTPS              Nginx + 中间件
DDoS               rate_limit.py + Nginx     中间件 + Nginx
SQL 注入            SQLAlchemy ORM            models 层自动防护
Token 窃取          JWT + HTTPS               auth 路由 + Nginx
敏感文件访问        .gitignore + nginx       项目配置
```

## 七、扩展性设计
